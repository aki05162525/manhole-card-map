# アカウント・記録・フレンドの設計

認証・記録・フレンドの判断基準。APIは `web/worker/`、DB定義は `web/migrations/` と `web/migrations-tombstones/`、復元手順は [配信手順](deployment.md#d1-を復元するとき) を参照。性能の目標は実測の保証ではない。

## 機能要件（決定済み）

- 認証はパスキー（WebAuthn）のみ。1アカウントに複数登録でき、改名・削除できる。使い捨ての回復コードを10個発行・再発行でき、使ったコードは無効になる。回復コードで入ったら新しいパスキーを登録させる。メールなどの個人情報は持たない。パスキーと回復コードを両方失ったら復旧できない。
- ログインしなくても地図・検索・詳細はこれまでどおり使える。
- 地図詳細の見出し右のスタンプ枠が記録の入口。未入手は今日の日付で保存し、入手済みの印を押すと編集欄を開く。フレンドの印は閲覧専用。一覧から直接開くカードページでは、カード番号・配布状態の下の記録欄で登録・日付とメモの編集・取り消しを行う。
- 記録はカードを入手したことだけ。日付とメモを付け、修正・取り消しできる。蓋の訪問・写真は扱わない。
- 地図で入手済みと未入手を区別し、「すべて／入手済み／未入手」で絞り込める。
- フレンドは招待リンクで申請し、相手が承認すると成立する。リンクは1人に1つで、フレンドの画面にいつも出ていて、期限はなく何度でも使える。作り直すと古いリンクは無効になる。送った申請の一覧・状態は送った側に見せない。フレンドは解除できる。ブロックは API と表にあるが、画面からは新しくできない（ボタンを外した）。前からのブロックはブロック一覧から解除でき、ブロックは相手に知らせない。
- フレンドにだけ、入手した枚数・どのカードか・入手した日・入手マップを見せる。メモは本人だけが見る。全体公開とプロフィールURLの共有はしない。
- 表示名を持つ。アカウントを削除すると記録・フレンド関係・パスキー・回復コードをすべて消す。書き出しは後回し。

## 構成

| 要素 | 方針 | 理由 |
| --- | --- | --- |
| API | 今の Worker `manhole-card-map` にスクリプトを足し、`assets.run_worker_first` で `/api/*` と、そこに挙げたページ（地図・一覧・about・規約・アカウント・フレンド・招待・カードページ `/card/*`。一覧は `web/wrangler.jsonc`）の HTML を Worker に通す。県ページ `/pref/*` は挙げていないので、静的資産が直接返す。ページは LINE のアプリ内ブラウザーからなら `?openExternalBrowser=1` を付けて302で転送し（パスキーを使える標準ブラウザーで開かせる。付いていれば転送しない）、それ以外は `ASSETS` からそのまま返す | 同じオリジンになり、CORS も Cookie の Domain 指定も要らない。JS・CSS・データ・画像は静的資産が直接返り、無料・無制限のまま（許諾を得たカード画像 `/card-images/*` だけは Worker が KV から返す。[デプロイ手順](deployment.md#カード画像)）。ページの表示は Worker の呼び出しとして数える。[C1][C2] |
| 画面 | URLごとの静的HTMLを保ち、ログイン状態でHTMLを出し分けない。設定・招待のページも静的に生成する。地図・一覧・フレンド（`/friends`）・フレンドの入手マップ（`/?friend=…`）・アカウント（`/account`）・about（`/about`）の間は、同じ文書の中で画面を切り替える（`web/src/app/`。Issue #260）。直接開いたとき・再読み込みは各HTMLから起動する。保持するのは地図と一覧だけで、フレンド・アカウント・about の画面は離れたらアンマウントする。読み取りの結果（フレンド一覧・受け取った申請・ブロック一覧・招待リンク、プロフィール・パスキー一覧・回復コードの残数）は、同じ文書の間、今の利用者（`session_mark`）に結び付けてメモリに持ち（`session/private-reads.ts`）、入り直したら最初の描画でそれを出して裏で取り直す。回復コードそのもの、ログイン・登録・再認証の途中、入力途中の値、確認ダイアログは持たない。メニューが開いたときや、切り替えるリンクへの `pointerdown`・`focus`・`pointerenter` で、その画面の束と（ログイン中なら）最初の読み取りを先に始める（地図の束はリンクへの `pointerdown`・`focus` のときだけ）。回復（`?recover`）、LINE 用のリンク（`openExternalBrowser`）、LINE のアプリ内ブラウザーでのフレンド・アカウント、招待・規約・県・カードのページは文書遷移のまま | HTMLのキャッシュ、`404-page`、SPAフォールバックなしを変えない。行き来のたびに地図を作り直さない |
| DB | D1 を2つ（本体の `manhole-card-map` と、復元後に削除を再適用するための `manhole-card-map-tombstones`。どちらも `--location=apac`）。read replication は使わない | フレンド・ブロック・記録の関係を SQL の一意制約と batch で守れる |
| 使わないもの | 記録・セッションの KV、Durable Objects、別 API ドメイン | KV は結果整合で、ログアウトやブロックの即時反映に向かない。[C7] Durable Objects を持つ Worker にはプレビューURLが作られない。[C5] 別ドメインは Cookie・CORS・配信が二重になる |
| カード台帳 | 静的 JSON のまま。D1 にはカードの表を持たない | 台帳の正本は Git と生成処理。二重管理を避ける |
| API の実装 | 小さな TypeScript の Worker。Hono は使ってよいが必須にしない。WebAuthn の検証は保守されているライブラリを使う | エンドポイントは30前後（`web/worker/routes.ts`）。安全性はフレームワークより認可の位置と SQL の制約で決まる |

`run_worker_first` と `not_found_handling: 404-page` の組み合わせは、固定している wrangler の版で、存在するページ・存在しないページ・`/cards.html` の転送・`/api`・Worker を通したページへの `_headers` の適用をローカルの workerd で確かめた（`web/worker/worker.test.ts`）。`run_worker_first` を外すと存在しないページが Worker に渡るので、この設定は必須。

### 地図との結合

- 未ログインでは今とまったく同じ。API を呼ばない。
- ログイン中は、HttpOnly のセッション Cookie とは別に、秘密を含まない表示用 Cookie を2つ出す。`signed_in=1` があるときだけ、地図の初期描画の後に自分の記録（カード番号と日付だけ）を取得する。メモは詳細を開いたときに取る。詳細では、入手済みかどうかと日付をその記録からすぐ出し、メモだけが後から届く。一覧にないカードは未入手としてすぐ出し、別のタブで付けた記録に備えて裏で同じ取得をする。一度取った詳細は同じ文書の間メモリに持ち、開き直すとすぐ出して裏で取り直す。メモが 400ms たっても届かないときだけ「記録を読み込み中…」を出し、届くまでは編集と未入手に戻す操作を受け付けない。詳細の取得が届く前に押した「入手したら押す」は、画面だけ先に入手済みにして、保存は取得を待つ（明示した空のメモは別のタブで書いたメモを消すため）。前に未入手と分かったカードを開き直し、裏の取り直しが届く前に押したときも同じく取り直しを待つ。記録がなければ保存を1回送り、すでにあれば送らずに届いた記録を出し、取得に失敗したら押す前の表示へ戻す。待つ間に詳細を閉じる・別のカードへ移る・利用者が替わる・ログアウトすると送らない（閉じた時点で送れない状態にし、開発時の StrictMode が同じ記録欄をすぐマウントし直したときだけ待ち続ける）。`session_mark` はセッションごとに変わる16桁の値（保存したトークンのハッシュをもう一度ハッシュして切り詰めたもの。そこからトークンや保存したハッシュは復元できないが、保存したハッシュを持つ者は計算して照合できる）。私的な API を呼ぶ画面（記録の Provider、フレンドの入手マップ）は、どれも `web/src/session/session-guard.ts` を通して呼ぶ。始めたときの印を覚え、送る直前と応答を受け取った時点で今の印と比べる。違えば要求を送らないか応答を捨て、別の利用者に替わったとみなし、前の利用者の記録・詳細・保留中の応答・絞り込みを捨てて取り直す（保存なら中止して、その旨を通知する）。ページへ戻ったときと画面を切り替える前にも同じく比べる。どちらも表示の切り替えの目安で、認可には使わない（認可は HttpOnly のセッションだけ）。
- 記録の一覧を取得できなければ「記録を読み込めませんでした」と出し、絞り込みを無効にして、どのカードも未入手と表示しない。詳細の取得に失敗したカードは、印を出さず、編集欄に状態とエラー・「記録を再読み込み」を出すが、「入手したら押す」は出さず、編集と未入手に戻す操作も受け付けない。
- 401 が返ったら（セッション切れ）、その要求が今の利用者のものなら、guard がそれを確かめるのと同じ同期の処理で表示用 Cookie を消して各画面へ伝え、画面は記録をメモリから消して、未ログインの表示に戻す。Worker は、新規登録・ログイン・回復・回復後のパスキー登録・ログアウト・アカウント削除の応答のほかは、401 を含めて Set-Cookie を付けない（AU-6）。前の利用者の遅れた 401 で、今の利用者の表示用 Cookie を消さないことは、画面が受け取った時点でも印を比べること（PF-5）が前提で、Worker だけでは保証しない。

`owns`）が通るときだけ描く。照合に失敗して画面を始め直す処理（`holds`）は、押したとき・応答を受けたときにだけ使い、描画では使わない。本人の記録（記録の Provider の一覧・詳細・通知）も同じで、Context・props で受け取る子の部品も、描画のときに照合する。記録の Context と入手マップが地図へ渡す値は、私的な値と一緒に、それを読んだ持ち主（`owner`）と照合の手段（guard の `owns`）を持ち、`useRecords()` が描画のたびに照合して、合わなければ私的な値（記録、詳細、フレンドの名前、通知、絞り込みに使う記録）を持たない読み込み中の値を返す（元の値ごとに同じ値を返す）。子の部品が写した値（記録の編集欄の下書き）も、写したときの持ち主と組で持ち、同じ照合が通るときだけ描く。招待ページの照会の結果（`self` と申請のボタン）も、照会した利用者が今の利用者のときだけ描く。(B) `web/scripts/lint/oxlint-guarded-exports.mjs`、どの応答で通知するかは `web/src/session/session-guard.dom.test.tsx`）。guard が拒否の理由を見分けられるように、私的な要求の失敗は本文のエラーコード（`{ error }`）まで読んで guard に渡す（記録の 404 の中に含め、読み終えた時点の印で成功も失敗も判定する。印が替わっていたら書き込みも読み込みも送らず、表示を消して取り直す。画面を離れたら（入手マップを隠したとき、招待ページを離れたときも）guard を閉じ、それより後の応答（401 を含む）を捨て、開いたままの再認証の WebAuthn ## 規模と費用

Worker要求の見積もりは、API、ページの文書取得、`/card-images/*` の画像取得を足して求める。対象パスの正本は `web/wrangler.jsonc` の `assets.run_worker_first`。同じ文書内の画面切り替えはHTMLを取り直さないが、APIや画像取得は別に数える。JS・CSS・静的JSON・背景地図の取得を一律にWorker要求へ足さない。Static Assetsから直接返す要求は無料・無制限で、Workerを実行してから `ASSETS.fetch()` で返す要求はWorker要求に数える。[C1][C2]

無料枠に収まるかは要求内訳と実績で判断する。実績はCloudflare GraphQL Analyticsの `workersInvocationsAdaptive` をWorker名・UTC期間で絞り、`sum.requests` を日別に取得する。これはサンプリングされ得る利用統計で、将来の負荷や課金明細そのものではない。取得期間・条件・値はPRに残す。ほかのWorkerも含めたアカウント全体の枠を別に確認する。[C17]

Workers Freeの要求枠はアカウントあたり10万件/日、UTC 0時（日本時間9時）にリセットされる。超過時、`run_worker_first` に一致する要求は429になり、静的資産へのフォールバックはない。したがってAPIだけでなく入口HTML・カード画像も止まる。Workerを通らない静的資産は引き続き配信される。[C2][C3] D1の日次読み書き枠の超過はD1のクエリを失敗させるため、影響はD1を使うAPIで、HTML・静的資産とは分けて考える。[C4]

| セッションの長さ | 最終利用から30日・最大180日 |
| 認証の試験環境 | 作らない。プレビューで API を無効にし、ローカルで確かめる。本番でしか起きない問題が続いたら別の Worker と D1 を考える |
| 達成率 | 出さない。出すときは現在の台帳を分母にして基準日を添える |
| CSP | 認証と同時に入れる |
| 法務の確認 | 専門家や窓口への確認はしない。規約は PR-7 のとおり書き、法令の適用は断定しない |
| ブロック | 画面からは新しくブロックできない（使われていないのでボタンを外した。API と表は残してある）。前からのブロックは、ブロックしている人がいるときだけ出るブロック一覧から解除できる。解除してもフレンドには戻らず、申請からやり直す |
| 送った申請 | 送った側には申請の一覧・状態を見せない（AZ-5） |

## 未確認

Rate Limiting binding を無料プランで使えるか（AU-10）、署名検証の本番の CPU 時間、Custom Domain への Access の効き方、Cloudflare 側の既定のログ保持、実機でのパスキーの対応状況、法令の適用。

WebAuthnの依存版は `web/package.json`、検証は `web/worker/auth-workerd.test.ts` を参照。ローカルの経過時間を本番のCPU時間として扱わない。Rate Limiting binding は実装に受け口があるが、`wrangler.jsonc` には未設定。
