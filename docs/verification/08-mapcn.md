## 実データの模擬計測

実カード1,313枚・ピン1,309件、実際のCARTO背景を使った。Chrome headless、412×823、DPR1.75、CPU4倍、遅延150ms、下り1.6Mbps／上り750kbps。新規コンテキストで初回、その後Service Worker保存を待って再起動、計3組。ブラウザーの版と各ビルドファイルのSHA256はJSONに記録した。

初回起動の中央値は7,250.3ms、再起動は2,336.5ms。選択クリックから一覧／詳細描画までの中央値は初回後227.2ms、再起動後121.1msだった。クラスタを拡大する操作の時間はこの選択値に含めず、最終クリックの処理・クラスタ葉の取得・UI描画を含める。

最初の再起動後にプログラムで移動とズームを繰り返した1回の記録では、requestAnimationFrame間隔の95パーセンタイルは33.4ms。これは待機区間を含むメインスレッドのコールバック間隔で、描画済みフレームのFPSやスマホで指を動かした感触の測定値ではない。

**初回3秒・再起動1秒・詳細100msの既存目標は未達。今回の結果で性能合格とはしない。** mapcn採用の理由はUIの統合と地図操作の設計であり、ライブラリ変更だけで軽くなったと判断しない。MapLibreの大きなチャンク警告も残っている。

再現手順（実データの通常ビルドを `bun run preview` で配信した状態で、webディレクトリから実行）：

```sh
RESULTS_DIR=results/mapcn ENGINES=mapcn MODES=full RUNS=3 node scripts/measure.mjs
RESULTS_DIR=results/mapcn node scripts/summarize-mapcn.mjs
```

集計は **ビルドを変更する前** に実行する。生のCDPログ・トレース・オフライン確認は `web/results/mapcn/` に保存する。巨大なトレースはGitに入れず、要約・各実行値・ビルドハッシュを `08-results.json` に保存した。記録後にmap破棄時のガード等を修正したため、ハッシュは最終PRのビルドではなく測定対象のビルドを特定する。

## 解釈の限界と次の確認

- Android / iPhone実機、低メモリ端末、長時間利用、実際のピンチ・慣性操作は未検証。
- CARTOの内容とCDN状態は変わる。前回のLeafletや自己配信PMTilesとは背景・条件が違い、過去値との単純比較でレンダラーの優劣は決めない。
- Service Workerはmap-ready後に比較用コードも含むassetsを保存する。Viteが旧比較用に出力するWorkerと新画面の自前Workerも別ファイルで保存される。初回操作中の通信量削減余地がある。
- 初回ready前の背景エラー・20秒の初期化タイムアウトでは一覧へ退避し、再表示には再読み込みが必要。表示後のタイル／フォントの部分的な通信エラーでは地図操作を維持する。
- CIの無地スタイルは挙動検査用。実背景の性能や契約条件を保証しない。
- 公開前にCARTO等の利用条件、背景配信、カードデータの確定・更新運用を決定する。

## CIで見つかったAPM復元の問題

APM 0.35.0は配置先ファイルだけでなくcheckout固有の配置履歴を使う。スキル本体をコミットしたfresh checkoutでは履歴がなく、frozen installが既存ファイルをスキップした後に古い配置として消し、auditが失敗した。ローカルの既存環境と、配置先が空の一時ディレクトリだけではこの問題を検出できなかった。

修正ではスキル本体を生成物としてGit対象外にし、manifest・lockに原典コミットと内容ハッシュを保存する。通常のfrozen installで復元し、auditで内容と配置を検査する。forceや監査の無効化は使わない。APM公式の「配置済みファイルもコミット」という一般的な案内とは異なるため、使用版に固有の対応として開発手順に明記した。

修正後は新規Gitクローン・空のAPMキャッシュ・Python 3.12に新規導入したAPM 0.35.0で、初回／2回目のfrozen installと監査10項目、Git差分なしを確認した。生成スキルを意図的に変更すると監査が失敗することも確認した。
