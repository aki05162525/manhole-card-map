# 技術検証 2：カード画像からのカード番号と蓋の座標の読み取り

実施日：2026-10-21
対象：カード画像 52 枚（GKP 一覧 2026-10-21 版から選んだもの）

## 目的

カード画像に印刷された次の2つを、自動で読み取れるかを確かめる。

1. 右上の枠のカード番号（例：`13-210-B001`）。一覧から作った番号の候補と照合する。
2. 左下の帯の蓋の座標（例：`35°42'00.9"N 139°30'25.3"E`）。

## 対象の選び方

- 一覧の 1,313 行から等間隔に選んだ 40 枚（北海道から沖縄まで、弾もばらける）。
- 一覧からの番号の候補が、画像名からの推定と食い違った 9 枚。
- 番号の候補を組み立てられなかった 3 枚。

画像は1秒間隔で取得し、保存済みの画像は取得しない（`cmd/fetchimages`）。

## 再現手順

```sh
go run ./cmd/fetchimages -list data/raw/gkp-list-20261021.html -indices <行の番号>
go run ./cmd/ocrcheck -list data/raw/gkp-list-20261021.html
```

## 画像のレイアウト

52 枚とも、カード番号と座標の位置、座標の書体と書式が共通だった。
画像の大きさは 513〜518 x 720〜722 で揺れるため、切り出す領域は画素ではなく比率で指定している。

## 結果

### カード番号

Tesseract（英語）で枠を1行として読み、番号の書式で取り出した。

| 結果 | 件数 |
|---|---|
| 一覧からの候補と一致 | 49 |
| 一覧からの候補と不一致 | 0 |
| 候補がなく、印字だけから読めた | 3 |
| 読み取れず | 0 |

- 番号の記号の位置には英字しか来ないため、そこで読まれた「1」と「0」を「I」と「O」とみなしている（佐渡市 `15-224-I001` が該当）。
- 一覧の候補が画像名からの推定と食い違った 9 枚は、すべて表の記号のほうが印字と一致した。画像名の末尾の `-02` などは画像の版を表しており、番号ではないと考えられる。

### 蓋の座標

最初に Tesseract で読んだところ、設定を変えても 52 枚中 40 枚前後しか書式どおりに読めなかった。
誤りの多くは字幅の狭い太字の書体で「3」と「8」、「5」と「9」を取り違えるもので、取り違えても日本の範囲内の座標になりうるため、書式の検査だけでは検出しきれない。

そこで、座標の帯はどのカードでも同じ書体と書式で印刷されていることを使い、テンプレート照合に切り替えた。

1. 帯を白黒にし、文字を連結成分として1文字ずつ切り分ける。
2. 背の高い文字を左から並べ、緯度は数字 7 個と N、経度は数字 8 個と E であることを確かめる。数が合わなければ読み取り失敗とする。
3. 正解ラベル（`data/ocr-labels.json`、目で読んだ 8 枚）から作った数字の見本と形を比べ、いちばん近い数字を選ぶ。

| 結果 | 件数 |
|---|---|
| 読み取れた | 52 |
| 読み取れず | 0 |

見本に使っていない 44 枚は、元の画像と読み取り結果を並べて目で確認し、44 枚すべてで一致した。
途中で、太字の「44」の横棒どうしがくっついて1文字に切り出される問題が見つかったため、幅が数字の 1.6 倍を超える塊を分割する処理を加えている。

## 限界と未確認の点

- 確認したのは 52 枚であり、全 1,313 枚での正しさは確かめていない。
- 番号と座標の読み取りは、どちらも人の確認を前提にした候補として扱う（要件定義の「カードの識別」と同じ扱い）。
- 座標の照合では、各数字の「いちばん近い見本」と「2番目に近い見本」の差を記録している。今回の最小値は 0.023、中央値は 0.045 だった。人の確認に回すしきい値は、全件を読んだあとに分布を見て決める。
- 読み取った座標が蓋の実際の位置として妥当か（自治体の範囲に入っているか）は確かめていない。

## 次の作業

- 全カードの画像を取得する（1秒間隔で 20 分強）。中断しても続きから再開できる。
- 全件で番号と座標を読み、候補との不一致、読み取り失敗、紛らわしさの余裕が小さいものを人の確認に回す。
- 座標が自治体の範囲に入っているかを、ジオコーディングの検証と合わせて確かめる。
