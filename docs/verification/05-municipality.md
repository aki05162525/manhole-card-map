# 技術検証 5：座標とカードの自治体の照合

実施日：2026-10-21
対象：全 1,313 枚の蓋と、技術検証 4 の5都道府県の配布場所

## 目的

座標を含む自治体を境界データから求め、カードの自治体と照合する。
これは人が確認する候補を拾うための補助検査であり、位置や番号の正誤を決める処理ではない。
住所、座標、カード番号、`data/overrides/cards.json` は変更しない。
技術検証 4 の9住所と借用住所50件の手確認は、今回の一致判定を理由に完了扱いにしない。

## カードの自治体の決め方

各座標に対して、印字番号による比較と一覧自治体名による比較を別々に出す。
両方の比較先が食い違っても、片方へ統一しない。
大郷町、長岡市 D001、新発田市 D001 は、一覧名から求めた自治体を印字番号で上書きしていない。

### 印字番号による比較

| 番号の扱い | 蓋の件数 | 比較する範囲 |
|---|---|---|
| PP-CCC が N03 の5桁コードと一致 | 1,150 | 該当する市町村または区 |
| 政令指定都市の市コード | 68 | N03 で同じ市名を持つ区の集合 |
| `13-100` | 43 | `13101`〜`13123` の特別区の集合 |
| CCC が `000` | 46 | 該当都道府県の全自治体の集合 |
| PP が `00` | 3 | 全国団体として対象外 |
| 現行 N03 のコードに対応しない | 3 | 比較先未解決として判定不能 |
| 合計 | 1,313 | |

政令指定都市は、N03 の `N03_004`（市名）と `N03_005`（行政区名）で区をまとめた。
市コードとの対応には、その市に属する最小の区コードを10単位で切り下げた値を使う。
今回の68件はこの方法で対応したが、未知のコードを無条件に丸めて既存自治体へ割り当てる処理はしない。
この対応方法は現在の N03 を対象とするものであり、将来のコード体系まで保証しない。

現行コードにない3枚は、大郷町の `04-442`、埼玉県下水道公社の `11-010`、東京都都市づくり公社の `13-010` だった。
後者2枚は `000` ではない団体用の番号で、市区町村コードと見なすことができない例である。
合併や区再編を理由にコードを旧コードから新コードへ置換した例はない。
歴史的な対応表を使っていないため、今後未知コードが出た場合も未解決として残す。

### 一覧自治体名による比較

全角と半角を正規化し、括弧内のカード記号などを除いて、都道府県内の N03 の名称と照合する。
「富士市 (B001) 岳南排水路管理組合」のように団体名が併記される場合は、空白で区切られた先頭の自治体名も候補にする。
東京23区と政令指定都市は区の集合、流域下水道や県名を伴う公社などは都道府県の集合として扱う。
これは対象範囲の設定であり、その団体の全施設が県内にあると確認したという意味ではない。

一覧名からの比較範囲は、市町村または区 1,168 件、政令市 68 件、東京23区 26 件、都道府県 48 件、全国団体 3 件となった。
印字が `13-100` でも一覧に区名がある17枚は、一覧名による比較ではその区に限定した。
比較先を解決できない一覧名は、この入力では残らなかった。

## 点と多角形の判定

`internal/municipality` に GeoJSON の Polygon と MultiPolygon を読む処理を加えた。
外周の内側から穴を除き、穴の縁も境界として扱う。
点が共有境界上にある場合は、候補の自治体をすべて返す。
外接矩形で候補を減らした後に辺との交差を調べるため、離島や飛び地も別々の多角形として扱える。

距離は、点の緯度で経度方向を縮めた局所平面上で、各線分までの最短距離を求めた。
球の半径は 6,371,008.8 m とし、経緯度のまま測った長さをメートルと見なすことはしていない。
数十 km 以上の距離は概算であり、測量精度の値ではない。
OCR や ABR の座標と JGD2011 の間の座標系変換は加えていない。
境界付近では測地系や元の座標の丸めも確認対象に含める。

`byCode.boundaryM` と `byName.boundaryM` は、それぞれの比較対象を構成する多角形の縁までの距離である。
区や市町村をまとめる際に多角形を結合して内側の境界を消す処理は行っていないため、対象の内側では内部の区界や市町村界までの距離が出る場合がある。
対象の外側から対象までの最短距離にはこの内部境界が近道として入り込まないため、境界付近の分類は外側の点に限って行う。
`nearestBoundaryM` は全国で最寄りの多角形の縁までの距離で、カードの自治体までの距離とは別である。
分類には `nearestBoundaryM` を使わない。

| 分類 | 判定方法 |
|---|---|
| 一致 | 含まれる自治体のいずれかが比較対象に属する。境界上も含む |
| 境界付近 | 別の自治体に入り、比較対象の境界から50 m以内 |
| 不一致 | 別の自治体に入り、比較対象の境界から50 mを超える |
| 対象外 | 全国団体、上書き記録で未確定の座標、座標なしなど |
| 判定不能 | 比較対象を解決できない、またはどの多角形にも入らない |

海上などで多角形に入らない点は、近くに境界があっても判定不能とし、理由を区別する。
今回、どの多角形にも入らない点は0件だった。
実際に出た判定不能はすべて、番号から比較対象を解決できない場合である。

### 境界付近のしきい値

対象の外に出た点のうち、最小の距離は三鷹市の蓋の 25.7 m、次に小さいものは四條畷市の配布場所の約 5,519 m だった。
この分布から、数十 m の差を別に確認する暫定値として 50 m を採用した。
境界データや座標の誤差が50 m以内と保証された値ではない。

一覧名による照合で、しきい値を変えた場合の件数は次のようになる。
同じ住所の別窓口を含め、蓋と配布場所を合計した件数である。

| 距離のしきい値 | 境界付近 | 不一致 |
|---|---|---|
| 10 m | 0 | 5 |
| 25 m | 0 | 5 |
| 30 m | 1 | 4 |
| 50 m | 1 | 4 |
| 100 m | 1 | 4 |
| 1,000 m | 1 | 4 |

## 再現手順

技術検証 3 の OCR、上書き記録、技術検証 4 の `data-c` による結果を用意する。
境界 ZIP が保存済みなら再取得しない。

```sh
# 初回だけ。実行前に上記の利用条件を確認する。
curl -L --fail 'https://nlftp.mlit.go.jp/ksj/gml/data/N03/N03-2026/N03-20260101_GML.zip' -o data/raw/N03-20260101_GML.zip
sha256sum data/raw/N03-20260101_GML.zip

gofmt -w internal/municipality cmd/municheck
go vet ./...
go test ./...

# 通常の go test は大きな外部データを要求しない。
# この環境変数を指定したときだけ、保存済み全国版で都庁と大阪駅を検査する。
N03_ZIP="$PWD/data/raw/N03-20260101_GML.zip" go test ./internal/municipality -run TestN03 -v -count=1

go run ./cmd/municheck -near 50 -findings docs/verification/05-findings.json
```

出力は `data/work/municheck.json` と `data/work/municipality-review.html` である。
`05-findings.json` は、今回 AI が行った原因分類の記録であり、番号や座標を変更する上書きファイルではない。
`-findings` を省略すれば自動照合だけを実行できる。
所見は2026-10-21版の入力に対するものなので、一覧や座標が変わったら流用せず確認し直す。
出力 JSON に境界 ZIP と入力ファイルの SHA-256、しきい値を保存する。

今回の主要な入力の SHA-256 は次のとおりだった。

| ファイル | SHA-256 |
|---|---|
| `ocr.json` | `2d4d43971e3b8f5d07b75d20aaf67c3c0f8917d1d5ad41bc22445ba35c975f24` |
| `cards.json`（上書き） | `b473a558e8170e195a81dbf89e4f39361afd0ae61ceaac213d61faeb17f9069e` |

合成データで内側、外側、穴、穴の縁、共有境界、頂点、離れた多角形、境界から約0.9 m外側の点を検査した。

市への集約、未知コード、海上、対象外、確認ページの生成もテストした。
`gofmt`、`go vet ./...`、`go test ./...` は通った。

## 確認用ページ

`data/work/municipality-review.html` をブラウザーで開く。
既存の `review.html` と同じように、カード画像、番号と座標の拡大画像、記録値、確認事項をカードごとに並べた。
既存の `review.html` は上書きしない。

確認ページは、確認候補36件（蓋14件、配布場所22件）と対象外6枚の計42節、カード単位では30枚を表示する。
候補には不一致と判定不能だけでなく、境界付近、以前の遠い9枚、粗い9住所も含む。
この件数は誤りの件数ではない。

1. 番号と座標の印字を画像と比べる。上書き記録が使われた場合は、採用元と既存の確認者も見る。
2. 配布場所では、施設名と元の住所、曜日条件、借用の有無を確認し、折りたたみ欄の保存済み一覧原文と比べる。
3. 番号側と一覧名側が食い違う場合は、両方を保持する。どちらの自治体を正とするか、この検査だけでは決めない。
4. 原因を判断できなければ「原因不明」のまま残す。公開に使う位置の確認は、後日、自治体や施設の根拠を取得して行う。

HTML はローカルの `data/raw/images/` と `data/work/crops/` を相対参照するため、ページだけを移動すると画像が表示されなくなる。
判定 JSON と確認ページには、今回の所見が AI によるものだと明記している。

## 限界と未確認の点

- 自治体内の別の場所を指す誤りは検出できない。市区町村代表点や、同じ自治体内で借りた住所は一致になりうる。
- 印字番号が全国地方公共団体コードに対応するという見なしには例外がある。番号の不一致を直ちに OCR の誤りとしない。
- 境界データは2026年1月時点、一覧は2026年10月時点で、作成時点が異なる。今回は年度差による不一致を特定していない。
- JGD2011との座標系の差や印字の丸めを補正していない。境界から25.7 mの三鷹市の例は人の確認を残す。
- N03には暫定境界がある。境界の数値計算ができることと、現地での所属の確定は異なる。
- 全国の多角形がどこでも正しいことを独立に検証していない。実データテストは2地点で、穴などは合成データで検査した。
- 原因分類に使ったのは保存済みの画像、一覧、確認記録だけである。自治体や施設の最新ページへはアクセスしていない。
