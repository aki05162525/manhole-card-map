## 採用根拠と検証

採用座標は建物代表点であり、室内の窓口・階の正確な場所ではない。同じ建物の平日窓口と守衛室には同じ点を使えるが、別館や別棟へ流用しない。

1. 公式施設ページの数値q、destination、施設名付きmarker、または県公式データの施設名・住所・緯度経度を照合。
2. 公式施設案内が埋め込んだGoogle地図では、iframe URLのviewport値を使わず、取得した埋込応答の `initEmbed` 内の**名前・住所付き施設レコード**にある座標を使った。原典は公式ページ、補助原本はそのページが明示的に参照する埋込地図。外部地図で独自に施設や住所を検索した値ではない。
3. 公式の短縮地図リンクは通常の転送でHTTP 200となり、施設名に一致する目的地 `!3d/!4d` が確認できたもののみ採用。`@lat,lng` の表示中心は不使用。HTTP 429 /sorry のcontinue引数に座標があっても不採用。

`provenance.json` はprimaryとsupportingSourcesを施設別に記録する。`adopted-manifest.json` は採用根拠の原本をこのディレクトリに揃え、元キャッシュ再利用時は実取得時刻とreusedFromを保持する。`manifest.json` は追加調査の取得記録。未解決attemptsには元地域キャッシュへの参照もあり、元ファイルは変更していない。元監査sourceUrlsに同市の別カード施設のURLが混じる場合があるため、そのリンクだけを施設同定根拠にはしていない。

`validate.py` は原典・補助原本341ファイルのハッシュ、全147対象の網羅・一意性、未確認配布の分離、既座標非上書き、採用された数値の原本存在、公式iframe/linkから補助原本への参照を検証した。結果は `validation.json`。これは数値・参照の再検証であり、現地確認を意味しない。

再生成と検証（ネットワーク再取得なし）：

```sh
uv run --with requests --with beautifulsoup4 python data/evidence/national/locations-chubu-west/build.py
uv run --with requests --with beautifulsoup4 python data/evidence/national/locations-chubu-west/validate.py
```
