## 根拠と座標

`manifest.json`は実際のURL、取得時刻、HTTP結果、リダイレクト先、原本パス、SHA-256。341 URLを取得試行し、327件HTTP 200、9件404、202/403/429/503/通信失敗が各1件。拒否応答の回避は行っていない。奈良企業局のみrequestsのTLSハンドシェイク失敗後、curlの標準TLSで取得できた。前の失敗もmanifestに保存した。

`snapshots/*.html`は取得したbytesそのもの。JPEGの画像2件も元のbytesを同じ命名規則で保存しており、実形式はmanifestのcontentTypeを参照する。`.txt`と`*-review.txt`は閲覧補助で根拠原本ではない。既存`.gitattributes`の`data/evidence/**/*.html -text`が適用される。

`approved_coordinates.py`の25件だけ採用する。松阪・四日市の公式配布先リンク、伊勢・吹田・泉佐野などの公式施設地図の目的地を名称住所と照合した。桑名2件は「配布場所・時間・座標」欄の度分秒を十進法へ変換。精度は施設・建物代表点であり、2階受付や守衛室の室内位置を表さない。

`coordinate-candidates.json`の候補は承認済み一覧ではない。高石・東近江・西宮・田原本などの蓋地図、亀山の駐車場、八幡の駐車場は施設座標として不採用。原田処理場全景・公園全景は管理事務所の位置まで対応できず不採用。松阪総合運動公園の地点も管理事務所との対応が不足するため不採用。

## 再現・検証

リポジトリルートで実行する。

```sh
python data/evidence/national/kinki/build.py
mise exec -- go run ./cmd/builddata -places data/overrides/regions/kinki.json -out data/evidence/national/kinki/build-check -as-of 2026-11-05
```

`build.py`は固定入力、明示的な判断、保存原本のみから生成する。再取得はしない。`fetch.py`は同一URLのキャッシュを再利用し、ホストごとに約1.1秒間隔を空ける。追加取得用URL一覧も保存している。`read_urls.py`の本文抽出は空のarticle要素等で本文を取りこぼす場合があるため、斑鳩などは原本全体のテキストを別途読み、採用した。

検証済み：全191カード・263原関係の収録、全原本SHA-256、承認座標の原典文字列、重複・孤立ID、immutable quality.jsonのsourceHashes、Goのschema・台帳適用。Go生成で25施設ピンを確認。結果は`validation.json`。検証出力の全全国データは重複保存を避け削除済み。

## 統合担当への注意

- コミット・push・PR・ブランチ切替は行っていない。変更は近畿の3所有領域内のみ。
- facility IDは初回割当`facility:kinki-<legacy token>`を固定IDとして使う。住所・名称更新に合わせて再採番しない。共有の松阪当直室、四日市総務課、大東、宇治田原、原田管理事務所、加東、狭山池等は明示的aliasで統合済み。
- sourceHashは2026-10-21基礎入力に対応する不変quality.jsonから採った。現GKPによる失効判定は親の統合処理に委ねる。新GKP HTMLは再取得していない。
- 新窓口はproposalまで。親側で明示的追加履歴へ変換するときも旧関係を削除しない。伊丹・橿原の「旧窓口終了」をカード全体終了と扱わない。
- 調査時点で、読んだ契約ドキュメントとGo実装の食い違いは見つからなかった。公式と基礎入力の差分・公式同士の相違は各カードのreviewNoteと上記に記録した。
